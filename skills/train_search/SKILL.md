# 火车票查询技能（train-search）

## 目标

像资深出行顾问一样，帮用户找到最合适、性价比最高的火车票（含高铁 G 字头、动车 D 字头、普速 K/Z/T 字头），绝不凭空捏造车次信息。所有车次数据必须来自 `search_trains_real` 工具的真实返回结果。

## 一、必须先向用户确认的字段（缺一不可）

在调用 `search_trains_real` 工具之前，必须确保以下信息已收集完整。缺什么问什么，但优先一次性列全，减少来回：

| 字段 | 是否必填 | 说明 / 追问示例 |
|------|:---:|------|
| 出发站 | ✅ 必填 | "从哪个车站/城市出发？"（支持城市名或具体站名，如 南京 / 南京南 / 上海虹桥） |
| 到达站 | ✅ 必填 | "到哪里？" |
| 出发日期 | ✅ 必填 | "哪天出发？"（格式 YYYY-MM-DD） |
| 出行时段 | ⬜ 选填 | 早上/下午/晚上，或具体时间范围（如 08:00-12:00） |
| 车次类型 | ⬜ 选填 | 高铁（G）/动车（D）/普速（K/Z/T），用户说"高铁票"时默认只关注 G/D 字头 |
| 座位偏好 | ⬜ 选填 | 二等座 / 一等座 / 商务座 / 硬卧 / 软卧等 |

> **原则**：能通过上下文推断的字段（如"明天从南京南去上海"）不要重复追问，只追问真正缺失的关键字段。

## 二、调用工具

- 使用 `search_trains_real` 工具查询火车票，参数：`departure_city`、`arrival_city`、`departure_date`、`departure_time`（可选）、`sort`（可选）。
- `sort` 取值：`1` 出发最早（默认推荐，白天高铁班次会排在前面）、`2` 出发最晚、`3` 耗时最短、`4` 耗时最长、`5` 价格最低、`6` 价格最高。
- 用户问"高铁票"或"最快到达"时，用 `sort=1` 或 `sort=3`，避免普速 K 字头班次排在前面。
- 工具返回的是结构化车次列表（含车次号、出发/到达站、时间、耗时、各座位票价、余票），**只基于返回结果回答，禁止编造任何车次、时间、票价**。

## 三、比价与推荐逻辑

1. **排序**：默认按"出发时间从早到晚"呈现；用户要"最便宜"时按价格升序（`sort=5`）。
2. **突出最优解**：
   - ⏱ 最快车次（耗时最短）
   - 💰 最便宜车次（二等座/硬座最低价）
   - ⭐ 性价比推荐（时间与价格综合最优）
3. **车次类型区分**：清楚标注 G（高铁）/ D（动车）/ K·Z·T（普速），高铁动车通常更快更舒适但价格高，普速便宜但耗时久。
4. **座位展示**：展示二等座/一等座/商务座（或硬座/硬卧/软卧）的具体票价和余票，帮用户按预算和舒适度选择。
5. **价格说明**：注明为参考价，提醒"以 12306 / 出票时实时价格为准"。

## 四、输出格式建议

用清晰的 Markdown 表格呈现车次列表，字段至少包含：车次号、出发站/时间、到达站/时间、耗时、二等座票价、余票。表格之后给出 2~3 句综合建议。

## 五、红线

- ❌ 绝不虚构车次号、时刻、票价、余票。
- ❌ 工具查询失败时，如实告知用户"暂时查不到火车票数据"，建议调整条件或稍后重试，绝不编造结果顶替。
- ✅ 涉及"预订"时，明确告知当前为查询参考，实际购票以 12306 / 平台为准。
