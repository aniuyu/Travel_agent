  1. 新增 content/middles/map_guard_middle.py：MapGuardMiddleware
     - `@wrap_tool_call` 拦截 build_map 调用，缓存其 map-json 代码块
     - `aafter_agent` 结束时比对最终回复：若调用了 build_map 但回复里丢了代码块，自动注入代码块到回复末尾
  2. travel_agent.py：get_agent() 加 `middleware=[MapGuardMiddleware()]`；【地图能力】提示词重写为"好例子/坏例子对照"，明确"代码块是回复主体、文字只能附注、没有代码块=任务失败"
  3. all_agent.py：主提示词加"子代理返回的 map-json 代码块必须原样转发"
- 验证：import 通过、_extract_map_json 提取正确、get_agent() 组装正常（9 工具 + 中间件就位）、awrap_tool_call/aafter_agent 钩子已注册
- 关键经验：deepagents 中间件钩子 = before/after_model、before/after_agent、wrap_model_call、wrap_tool_call（异步版加 a 前缀）；aafter_agent 返回 {'messages':[AIMessage(...)]} 可追加到最终回复；wrap_tool_call 拦截时用 request.tool_call.name 拿工具名、handler(request) 返回的 ToolMessage.content 取结果
- 注意：中间件实例是子代理级单例，缓存用实例属性 self._latest_blocks（agent 结束时清空，避免跨会话残留）

### 第二十三轮：地图稳定性加固（用户反馈"时好时坏，下次可能又崩"）
- 根因分析：TravelMap 之前所有 AMap 对象创建（Map/Marker/Driving/Polyline/Bounds/Traffic）都裸奔无 try/catch，任何一处抛错都导致整个 React 组件崩溃（Runtime Error 白屏）；且多个地图组件同时 mount 会重复注入 <script>、window.AMap 判断有竞态；坐标类型无校验（LLM 偶发输出字符串/NaN）
- 加固方案（防御式重写 TravelMap.tsx + 新增 ErrorBoundary.tsx）：
  1. SDK 加载器模块级单例 Promise（loadAMapSDK）：去重 + 防竞态 + 失败缓存可重试
  2. 所有 AMap 对象创建独立 try/catch，失败只 console.warn + 跳过，"能画多少画多少"，绝不崩组件
  3. 坐标数值校验：typeof number + Number.isFinite，非法坐标直接跳过（打点/路线/中心点都校验，中心点非法回退北京天安门）
  4. TileLayer.Traffic 单独 try，路况图层不可用不影响地图主体
  5. 新增 ErrorBoundary.tsx 组件，markdown-text.tsx 里包住 TravelMap，极端异常也不会拖垮整条消息
  6. 路线规划坐标 Number() 强转 + coordsValid 校验，避免 AMap 内部抛错
- 验证：tsc --noEmit 通过
- 经验：第三方 SDK（高德/百度等）前端集成必须"每个对象创建点都独立 try/catch + 坐标/参数合法性前置校验 + ErrorBoundary 兜底"，否则一个 API 兼容性问题就白屏
