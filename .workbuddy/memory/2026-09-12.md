## 修复：用户额外要求（车次/酒店）在行程里"对应描述不真实"

### 现象
- 用户截图：填了「额外要求：我想坐 Z375，想住上海外滩金陵东路桔子水晶酒店」，
  但生成的行程描述里根本没体现，AI 自己编了别的车次/酒店

### 根因（两层）
1. **LLM 根本不知道用户写了啥**：`conn/trip_planner.py` 里 `extra_notes` 字段
   **只被存进 payload**，没被喂给 `_ai_summarize` 的 prompt → AI 当然编造内容
2. **真实数据查询无优先级**：途牛 `searchLowestPriceTrain` 只返回最便宜的几趟，
  途牛 `tuniuHotelSearch` 按综合排序，都不一定命中用户指定的车次/酒店

### 修复
1. **AI 总结 prompt 透传 extra_notes**（`conn/trip_planner.py` 的 summary_prompt）
   - 加 `notes_section`：含意图词「想坐/想住」时整段塞进 prompt
   - 显式指令：「如果用户提到具体车次号（如 Z375），summary 必须原样提到」

2. **新增结构化提取 + 置顶逻辑**
   - `_extract_specified_train(notes)`：正则 `[A-Z]{1,2}\d{1,4}` 抓车次号，
     但只在含意图词（坐/乘/搭/订/买/搭乘）时才返回，避免「Z375 经过南京」误抓
   - `_extract_specified_hotel(notes)`：正则 `…酒店|宾馆|客栈|民宿|公寓` 抓酒店名，
     同样要意图词（住/订/入住/想换）
   - 抓到了就置顶 tickets/hotels 列表第一条
     - 已有同名：移到首位
     - 没匹配：插入一条 `user_specified=True` 记录，标 `tag: '您指定'`
       - 列车时刻用 `—` 占位（提示用户查 12306）

## 修复：「新建行程」切换 tab 后表单内容丢失

### 现象
- 用户反馈：填了一堆字段（目的地/日期/预算/偏好/额外要求），切换到别的 tab 再回来，
  全部回到默认值（"新建行程"白板）

### 根因
- `src/app/workspace/page.tsx` 里 `CreateTripPanel` 是个 client component
- 主区用 `tab === "create" && <CreateTripPanel ... />` **条件渲染**
- 切走 tab → React 把 panel 卸载 → 所有 `useState` 销毁 → 切回来重新挂载 → 默认值

### 修复
新建行程表单整个状态落到 `localStorage["fy_create_trip_draft"]`：

- 模块级 helpers：`loadDraft()` / `saveDraft(d)` / `clearDraft()` + `CreateDraft` 类型
- 每个 `useState` 改成 `useState(() => loadDraft().xxx)` 懒加载初始值
- 加一个 `useEffect` 监听所有字段，**任一变化**就 `saveDraft(...)` 写回
- **提交成功后** `clearDraft()` 清空，避免下次打开还看到上一轮
- 底部加个「清空草稿」小按钮，用户主动重置（且顺手 setState 把 UI 同步回默认）

### 关键点
- 不能简单"提升到父组件 state"——父组件 `WorkspaceContent` 是 `useState`，理论上保留；
  但 **tab 切换走的是 `router.replace` URL 变化**，整个 workspace 子组件树会重渲染。
  而且即使不重渲染，刷新页面也会丢。**localStorage 才是真稳**。
- 其他 panel (`SelectPlanPanel` / `TripDetailPanel`) 的状态本来就在父组件的
  `lastShareId` / `lastTripInfo` 里，父组件不卸载所以不会丢，**这次不用改**。

### 验证
- TS 编译 0 错误
- 浏览器 bundle 含 `fy_create_trip_draft` / `loadDraft` / `saveDraft` / `clearDraft` / "清空草稿"
- 工作流：
  1. 填字段 → 自动存 localStorage
  2. 切到「主页」看一眼 → 切回「新建行程」→ 字段都还在
  3. 刷新整个页面 → 字段也都还在

## 车票/机票：修复车型缺失 + 分页 + 实时余票弹窗

### 现象与需求
1. 查「全部」时看不到普速火车（K/T/Z），只有高铁和飞机
2. 车次太多需要分页
3. 点「预订」要弹出**实时余票**：火车各席别（无座/硬座/硬卧…）+ 价格；机票各舱位 + 价格

### 根因（车型缺失）
- `/api/tuniu` 火车查询用了 `searchType: "5"`（**票价升序**）
- 实测：`searchType=5` 返回 30 条**全是普速**（K/T/Z，因为最便宜）；`searchType=1`（时间序）才是混合的
- 而且每页固定 30 条 + 没有分页 → 用户只能看到某一类车

### 后端改动（`src/app/api/tuniu/route.ts`）
1. **火车默认 `searchType=1`**（出发时间升序）→ 车型自然混合
2. **分页**：
   - 火车首次返回 `queryId`；翻页传 `queryId + pageNum`（不需要城市日期，加了 `isTrainContinue` 判断跳过参数校验）
   - 机票翻页传 `pageNum`
   - 响应加 `pageNum` / `queryId` / `hasMore`（`data.length >= 20` 视为还有更多）
3. **新增 `type=train-detail`** → 调 `queryTrainDetail`，返回 `seatInfo[]`（`seatName` / `price` / `leftNumber` / `seatStatus`）
   - **坑**：内层返回多一层 data 包裹 `{successCode, data:{trainInfo, seatInfo}}`，要 `result?.data ?? result` 兼容
4. **新增 `type=flight-detail`** → 调 `multiCabinDetails`，返回 `cabinInfo[]`
   （`cabinClass` / `basePrice` / `totalTax` / `totalPrice` / `remainingSeats` / `baggageInfo` / `refundChangeRule` / `buyCondition`）
   - 过滤 `buyCondition === "null"` 字符串
   - flightNo 回填（接口返回里没有）
5. **车型判断重写**：搜索接口 `trainType` 只给 `"direct"`，区分不了 → 新增 `trainCategory(车次号)`
   按前缀：G 高铁 / D 动车 / C 城际 / Z 直达 / T 特快 / K 快速 / 纯数字 普快
   - `TicketResult` 加 `category` 字段

### 前端改动（`TicketsPanel.tsx` 重写）
- **车型筛选**：「全部 / 🚄 高铁动车(G·D·C) / 🚂 普速列车(Z·T·K·数字)」
  - 机票不受车型筛选影响；筛选后无结果显示提示 + "查看全部车型"按钮
- **分页**：底部「加载更多班次」按钮（仅 `dataSource==="live" && hasMore` 时显示）
  - 火车走 queryId 续页；合并结果后重新按时间排序
- **余票弹窗**：点「预订」→ `openDetail(ticket)`
  - 火车 → `train-detail`，展示席别卡片（席别名 / 余票数 / 价格 / 预订按钮，无票置灰）
  - 机票 → `flight-detail`，展示舱位卡片（舱位 / 含税总价 / 基础价+税 / 余票 / 行李额 / 退改 / 购买条件 / 订按钮）
  - 带 loading 态 + 错误重试
